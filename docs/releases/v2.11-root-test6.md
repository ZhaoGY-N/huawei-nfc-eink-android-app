本测试版新增 Shizuku Root 下的 SN220 HAL 注入适配，并统一 Shizuku Shell / Root 会话入口；新增内置色阶测试图。延续 v2.10-test1 的 A0 / A1 布局与屏幕类型选择。

## 更新

- 移除 App 直接 `su → app_process` 的独立执行链，统一由 Shizuku UserService 管理。Root 服务负责底层准备，worker 以 UID 2000 + shell SELinux 域进行 NFC 通信；界面显示实际后端身份。
- 新增默认关闭的“SN220 Q-Poll 兼容”实验选项，需要 Shizuku Root 和 arm64。正则匹配 `nfc_nci` 命名族，保留函数/GOT 校验与多候选拒绝；覆盖 `write_internal`、`write_unlocked` 发送路径及入站通知转换。只修改 HAL 进程内存，不写 NFC 固件、系统 HAL 文件或屏幕 DB / DA。
- 增加发送/接收调用与改写计数、兼容开关状态和有限的寻卡 NCI 采样，便于定位“注入完成但没有标签”的问题；不采样 APDU、PIN 或图像。先关闭兼容改写再恢复普通寻卡，失败时明确提示恢复未确认。
- D1 的 C0 字段接受已登记的 `201EA001` / `00000001` 两个完整值，未知值仍在认证和写入前拒绝，不任意放宽前缀。
- 新增“图像与发送 → 编辑图片 → 色阶测试图”：16 级灰阶、黄色/红色的 17 级色阶、连续渐变及四色基准。保留原四色测试图，不自动改变图像处理参数。

## 安装与测试

覆盖安装 APK 后重新打开应用并连接 Shizuku。常规系统 QTag 后端保持默认；仅在测试注入适配时勾选 SN220 实验选项。通过 Root 启动 Shizuku 前，请在 Magisk / KernelSU 中给予相应权限。

先做芯片检查、Q-Poll 寻卡和“只读检查屏幕”，通过后再选择正确的 A0 / A1 类型并发送测试图。色阶比较建议选择原始细节、关闭二值化，再分别开关抖动。

## 验证与已知限制

- Java 协议、图像量化/预览、两种面板布局、连接恢复及后端权限回归通过；原生 NCI 改写、HAL 正则识别和诊断回归通过，Clang 静态分析、APK 构建及签名验证通过。
- 已在 Xiaomi 25102RKBEC / myron（SN220U，`nfc_nci_nxp_snxxx_v2.so`）验证注入寻卡、D1、D3 上传、D4 返回 `9000` 和恢复握手。统计确认其发送路径经过 `write_unlocked`。用户报告显示成功，但已记录的刷新轮次最终 DE 返回 `68CA`，App 尚未确认忙→空闲完整周期；供能与完成状态仍需继续验证。
- 不保证所有 SN220 / ROM 通用兼容；fork 作者的小米 14 尚未在本分支实机回归。未默认加入双 PIN 验证或 fork 的固定刷新时序，也不解决不同板内驱动/面板初始化不匹配。
- 兼容库会驻留到 HAL 进程重启；会话开关正常结束时删除，异常强杀时有最长 360 秒失效限制。可升级本应用自身的旧 hook，其他来源的 hook 仍会拒绝。

APK 与 SHA-256 校验文件见附件。本版本为预发布测试版。
