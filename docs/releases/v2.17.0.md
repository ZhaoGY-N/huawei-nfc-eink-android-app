# QPollLab v2.17.0

本版整合图像处理、发送与编辑界面、Shizuku / Root 兼容选项，并修复覆盖安装后驻留服务继续引用旧 APK、导致后端退出码 134 的问题。

**版本名称：2.17.0；内部版本：33；最低 Android 8.0（API 26）。** 下载附件中的 `QPollLab-2.17.0.apk`，校验文件为 `QPollLab-2.17.0.apk.sha256`。

## 界面与图像功能

- 页面拆分为“发送 / 编辑 / 设备 / 设置”。发送页保留最终预览、发送操作、进度与结果，编辑页提供独立预览和构图、色彩及其他调整；两处预览使用同一份发送像素。
- 最近图片以两列大缩略图显示，支持再次选用、单条删除与清空。本地保存原图和编辑草稿，重新打开可恢复裁切、旋转与编辑状态。
- 支持亮度、色温、对比度、二值化、阈值、抖动、色块简化，以及相册照片四色取样和手动校色。内置四色、色阶、校色基准和纯色测试图保留独立规则。
- A0 / A1 / A0X 作为并列选项。A0X 用于已确认的左右半幅顺序差异，不作为任意镜像或半宽压缩问题的通用修复。
- 发送前可设置 0–30 秒充能；保留上电等待、状态查询间隔、阶段进度和计时。新增最长五分钟的仅供能功能，便于配合外部仪表寻找耦合位置；不读取屏幕或发送刷新 APDU。
- 失败结果直接展示原始错误、屏幕 SW、控制器状态或后端退出码，连续错误和恢复失败不会覆盖前面的具体原因。

## 通信与兼容选项

默认仍为 **Shizuku 用户服务＋系统 QTag**。原有执行方式、寻卡选项及默认规则保留，失败后不自动换路或重发图像。

| 执行方式 | 通信身份与用途 |
|---|---|
| Shizuku 用户服务（默认） | NFC worker 使用 UID 2000 / shell；Shizuku Root 可先准备 HAL，再切换身份通信 |
| Shizuku 进程兼容 | 绕开部分 ROM 的 UserService 启动异常，仍以 Shell worker 通信 |
| Root 直连（旧版） | 无需 Shizuku，以 UID 0 调用系统 NFC 服务；部分 ROM 会拒绝该身份的 ReaderMode |
| 前台 App 通信＋Root HAL（实验） | App 通过公开 ReaderMode / IsoDep 寻卡和刷屏，Root 只准备、保持和关闭 HAL 改写 |

- HAL 兼容层统一接受 SN220 / SN220U / SN100U 固件配置；仍要求 Root、arm64 和实际 HAL / 符号匹配。补充 `libnfc-nci.conf` 配置读取路径，原有配置路径优先级保持不变。
- 前台路径可选择 Shizuku Root 用户服务、Shizuku Root 进程兼容或直接 Root 管理 HAL。其 Q-Poll 固定使用 HAL 兼容寻卡；普通 NFC-A 对照只取得会话锁，不注入 HAL。
- 保留隐藏 ReaderMode 四／五参数自动适配和“直接 Q-Poll”实验选项。公开前台路径不依赖隐藏 ReaderMode 的签名。
- 新旧路径共用会话锁；停止、离开前台或管理通道失联时清理。关闭改写开关后释放 ReaderMode，清理失败会明确报告。HAL 库按原实现驻留至 HAL 进程重启。

## 修复覆盖安装后的后端崩溃

驻留的 Shizuku 服务此前仅在构造时保存 APK 路径。覆盖安装改变目录后，服务可能向 worker 传入已删除的旧 APK，导致 `ClassNotFoundException: QPollWorker`，在部分系统上表现为 ART 崩溃和退出码 134。

现在两个驻留后端每轮都会向系统查询当前 APK，并验证应用 UID、文件可读性与 `classes.dex`。路径变化会记录 `APK_REFRESH`；无效包在 NFC 操作前报错。用户服务版本同步更新，避免继续沿用旧实现。

## 使用与验证范围

- 首次使用先完成设备设置，按实物选择屏幕类型。兼容选项位于“设置 → 执行方式与兼容实验”。更换组合后先做寻卡和只读 D1，再决定是否刷图。
- 保留原厂驱动、屏幕规格检查、单次 PIN、传图、D4 与忙闲判断；不会自动重放已经开始的写入。刷新期间保持贴合并保持 App 在前台，中断可能留下不完整画面。
- 完整 Java 回归、APK 构建和 v2 / v3 签名检查通过；原协议和图像导出的 12 个基线文件逐字节一致。原生 Hook 源码和二进制没有改动。
- K90 Pro Max（25102RKBEC / SN220U）上，默认组合完成完整刷新，用户确认实物画面正常；前台 App＋Root HAL 完成 D1、上传、D4、忙→连续三次空闲及恢复。再次覆盖安装后，原驻留用户服务未重启，自动刷新 APK 路径并正常工作。
- 2.16.1 与本版 HAL 后端对照均通过只读 D1。“直接 Q-Poll”在这台手机的两版测试中均未通过命令响应及恢复确认，仍作为实验选项，不建议该机优先使用。
- **SN100U 的准入扩展不等于所有 SN100U 手机已验证。** 本版仍缺少 SN100U 实体设备验证；其他 ROM、管理通道及完整组合的兼容性需要分别测试。D1、传图或 D4 成功不能单独替代刷新周期和实物确认。

与本仓库此前同签名版本可覆盖安装并保留数据；其他分支或重签名 APK 可能无法直接覆盖。参考项目与第三方许可证说明继续保留在仓库和 App 内。
