# v2.19.1 — Multi-level chart preview and original-image comparison

## Preview fixes

- Both multi-level charts now use a dedicated, isolated rendering path. They no longer inherit binary threshold, block simplification, image adjustments or stale settings from the previous photo.
- Exact source black and white endpoints are retained through quantization. A chart that unexpectedly collapses to one output colour or emits an invalid code fails with a visible error instead of silently displaying a black frame.
- Test-card preview pixels are mapped directly from the final logical 2-bit codes to the display palette. Preview no longer depends on the panel-specific A0/A1/A0X pack/unpack path; the actual outgoing payload remains independently packed for the selected panel type.
- Each prepared image caches a panel-fitted source preview alongside the final four-colour preview.

## Press-and-hold comparison

The editor's **Colour** tab includes **按住查看原图**. Touch down temporarily displays the source image before colour adjustments and four-colour quantization; touch release or cancellation restores the final sending preview. Page navigation and Activity pause/stop also release the comparison state. This only switches the displayed bitmap and never alters the prepared send payload.

## Verification

The Java offline regression suite passes, including new multi-level chart tests for all six mixing presets, all four Reink recipes, exact endpoint preservation, direct preview-pixel mapping and invalid / single-colour guards. Full Android SDK/NDK packaging, UI touch testing on a device and physical e-ink output have not been verified in this environment.
# v2.19.0 — Four rendering recipes and self-bootstrapping unsigned build

## Rendering

The original project now exposes the four `qpoll-lite-main` / Reink Case recipes in the editor:

- **鎏金** — unmodified RGB input, red-mean nearest palette and Atkinson error diffusion.
- **质感** — the documented 4×5 LOMO matrix followed by the same Atkinson path.
- **色阶** — nearest palette only, without error diffusion.
- **水墨** — BT.601 grayscale followed by Atkinson.

The recipe selector is separate from the existing six calibrated colour-mixing presets. The first selector choice keeps the original pipeline intact. The four imported recipes can consume the project's saved measured palette without changing the four panel wire indices. Brightness, temperature and contrast remain active for regular photos; binary threshold, block simplification and the old manual dithering checkbox are not applied on these four paths.

The new multi-level style chart (the original pipeline as a baseline plus the four imported recipes) uses fixed chart artwork and the saved measured palette (or factory defaults if no measured palette exists). Switching the four recipes does not change the chart source or reuse edits from the previous photo. Existing regular-photo drafts remain restorable after leaving the chart.

## Build

`build.bat` is the Windows entry point. It requires only:

- `JAVA_HOME` pointing to a full JDK 17+ installation.
- `ANDROID_HOME` pointing to the SDK destination directory.

It uses a preinstalled Python 3.9+ if available; otherwise it bootstraps the official Python 3.12.10 embeddable runtime into the ignored `tools/` folder. `build.py` then bootstraps Android command-line tools from Google's SDK repository, presents SDK package licences for explicit user acceptance, installs `platforms;android-34`, `build-tools;34.0.0` and `ndk;27.2.12479018`, fetches missing Shizuku 13.1.5 AARs if needed, compiles the project's arm64 native sources with NDK Clang/LLD, runs Java-only regression tests and assembles an aligned unsigned APK.

The output is `dist/QPollLab-2.19.0-unsigned.apk` plus its `.sha256` file. No signing step is performed. Sign it with your own key before installation. `build.py` can also be invoked directly with Python 3.9+; `build.sh` is the POSIX wrapper and expects Python 3.9+ to be installed.

## Verification status

The Java regression suite passes, including the four recipe tests and all existing protocol, image, panel layout, calibration, session and backend tests. Full Android toolchain installation, NDK native compilation and APK assembly remain unverified in the current environment because it has no installed Android SDK/NDK and cannot reach external download hosts. A connected Windows build host should perform the first full bootstrap/build. Actual colour appearance still requires comparison on the physical panel.
# QPollLab v2.18.0

**版本名称：2.18.0；内部版本：34；最低 Android 8.0（API 26）。**

## 四色混色算法实验

- 六种预设可在“设置 → 屏幕校色”选择，A0 / A1 共用并保存在本机。
  1. 原版：线性 RGB 最近色 + Floyd–Steinberg，保持旧版输出，作为对照。
  2. 感知：OKLab 最近色 + Floyd–Steinberg。
  3. 比例：四色比例分解 + Floyd–Steinberg。
  4. 比例：四色比例分解 + Bayer 8×8。
  5. 比例：四色比例分解 + Jarvis–Judice–Ninke（JJN）。
  6. 比例：四色比例分解、不抖动，用于比较不做空间混色时的输出。
- 比例分解在实测四色的线性 RGB 凸包内求目标色的覆盖比例；超出色域时使用凸包最近面、边或顶点作为近似。近中性像素仅允许黑白混合。四色比例不是对真实颜料光谱的精确预测。
- 新增 552×768 混色多阶色卡，固定包含灰阶、黄、红、橙、肤色、绿、蓝、紫八行，每行九个白→目标色→黑色阶及连续渐变。所有预设对同一输入色卡处理，方便同条件比较。
- 在“设置 → 屏幕校色”可以直接打开色卡，也可在“编辑 → 测试图”中选择。色卡使用当前测量色板，即使普通图片的校色开关关闭也可执行；普通图片只有启用校色后才使用所选预设。
- 混色色卡不受裁切、旋转、二值化、色块简化、抖动开关和整体调整影响。退出色卡可恢复进入前的编辑图片。校色基准图仍使用固定原色编码，不受混色算法影响。

## 已知限制与测试建议

- 当前色彩预测仍基于拍照取样的 sRGB 颜色，不含真实颜料的光谱反射、相邻像素串扰、点阵方向效应、屏幕温度和环境照明模型。
- 建议在固定照明和相机曝光 / 白平衡下完成四色取样；每次只切换一个预设，等待屏幕完整刷新后比较同一色卡。重点比较橙色、肤色、灰阶和高饱和色区域。
- 旧版算法保留为基准，不自动替换。切换算法不触发 NFC 刷写；仍需用户确认发送。

## 离线验证

原有 Java 离线回归全部通过。新增 ColorMixTest 覆盖六种算法输出范围、旧版入口与新入口的逐像素兼容、中性灰黑白保护、Bayer 确定性和 JJN 两行误差扩散边界。

完整 Android APK 构建、手机界面交互和实体屏幕刷新尚未在当前环境执行。
